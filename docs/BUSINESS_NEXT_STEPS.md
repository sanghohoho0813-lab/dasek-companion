## 2. 실제 매장 운영으로 가려면 (다음 단계)
1. **공통 데이터베이스** — 직원 휴대폰·카운터 PC 가 같은 데이터를 보도록 (현재 설계된 Supabase 초안을 연결)
2. **실제 회원 로그인** — 휴대폰 번호 인증 등, 개인정보 최소 수집
3. **서버에서 지키는 권한** — 직원/책임자 권한을 화면이 아니라 서버에서 확인
4. **쿠폰·보상 서버 처리** — 위변조·중복 지급을 서버에서 막기
5. **실제 메뉴·가격·사진** — 매장이 직접 고칠 수 있는 화면은 이미 있음 (운영 AX → 메뉴·고양이 사진)
6. **개인정보 처리방침·보안 점검**
7. **매장 1곳 파일럿** — 2~12주, 직원 확인 방문·재방문 수를 처음부터 기록

자세한 점검표: `docs/LIVE_TRANSITION_CHECKLIST.md`

## 3. 이후 유료 웰니스 사업 (대표 기획안 연결)
| 서비스 | 지금 쌓이는 근거 | 먼저 필요한 것 |
|---|---|---|
| AI 개인 맞춤 식단·영양 기록 | 확인 구매 기록 | 메뉴별 영양정보 검증, 민감정보 동의 |
| 가족 식단 | 회원별 저장·구매 | 가족 단위 계정 설계 |
| 냉장고 재료 레시피 | 메뉴 재료 구조 | 레시피 콘텐츠 권리 |
| 정기픽업·식단 구독 | 저장 메뉴·재방문 주기 | 결제·환불·약관 |
| 반려묘 생활관리 | 고양이 프로필·성향 기록 | 수의학적 판단이 아닌 범위 정의 |
| 휴식·정서 웰니스 | 방문 시간대·관심 등록 | 비의료 표현 기준 |
| 제휴 상품·커머스 | 관심 등록 수요 집계 | 제휴처·정산 |
| 다른 매장용 AX·SaaS | 지금 운영 AX 구조 | 다중 매장·계정 구조 |

## 4. 대표가 정해야 할 것
1. 파일럿 매장과 기간 (다색냥 1곳부터?)
2. 회원 혜택의 실제 값 (가입 쿠폰·스탬프 10개 보상·추천 보상) — 지금은 예시
3. 직원 몇 명이 어떤 기기로 확인할지 (카운터 PC / 직원 휴대폰)
4. 알림 채널 (앱 안 알림만 / 카카오 알림톡 비용 포함)
5. 고양이 11마리 정보·원본 사진, 전체 메뉴·가격 제공 일정
6. 첫 번째 유료 서비스 후보 (정기픽업 vs 식단 구독 vs 방문 패스)

## 5. 지금 버전의 정직한 한계
- 숫자는 모두 DEMO 시연 데이터입니다.
- 손님 화면과 운영 화면이 이어지는 것은 **같은 브라우저 안에서**입니다. 다른 기기 사이 실시간 연결은 2단계(공통 데이터베이스)에서 됩니다.
- 자동 테스트가 통과했다는 것은 '규칙대로 동작한다'는 뜻이지, 실제 손님·직원이 써 본 검증은 아닙니다.
