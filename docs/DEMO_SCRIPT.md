# 발표 대본 — 다색컴패니언 시연 (5~7분)

**주소:** `https://dasek-companion-522v.vercel.app/demo`
**대상:** 김서윤 대표 (리얼식단·다색냥)
**한 문장:** 손님이 가입하고, 매장에 오고, 혜택을 받고, 다시 오도록 관리하는 과정이 손님 앱과 매장 운영 프로그램에서 하나로 이어집니다.

---

## 0. 시작 전 (발표 10분 전, 1분)
1. 발표용 노트북에서 위 주소를 엽니다 (화면 폭 1440 이상 권장).
2. 오른쪽 위 **처음부터** → **처음부터** (이 브라우저의 시연 데이터만 초기화. 다른 사이트 정보는 그대로).
3. 왼쪽 위에 `1 / 8`, 오른쪽에 휴대폰 화면과 PC 화면이 모두 보이면 준비 끝.
4. 청중 화면에 메모를 숨기고 싶으면 **발표 메모** 를 누릅니다.

> 화면 이동: 키보드 → / ← 또는 아래 **다음 / 이전**. 팝업이 열려 있으면 키보드로는 넘어가지 않습니다(Esc 로 닫기).

---

## 1단계 · 다색컴패니언은 무엇인가 (40초)
**말:** "왼쪽은 손님이 쓰는 휴대폰 앱, 오른쪽은 매장에서 쓰는 운영 프로그램입니다. 둘이 같은 데이터로 이어져 있습니다."
**가리킬 곳:** 오른쪽 PC 화면 위쪽 "오늘의 매장 운영", 시계, 왼쪽 아래 김서윤 대표 프로필.

## 2단계 · 손님이 둘러봄 (40초)
**말:** "다색냥 고양이는 매장 카드에 있던 실제 14마리입니다. 나머지 11마리는 정보를 받으면 넣습니다."
**가리킬 곳:** 휴대폰 화면의 고양이 사진·품종·성별. (사진은 카드 촬영본이라 작게 보여 드립니다 — 원본을 받으면 교체)

## 3단계 · 친구 추천으로 가입 — 시나리오 A 시작 (40초)
**누를 것:** **고객 · 추천 코드로 가입하기**
**보일 것:** 휴대폰 → 쿠폰함에 가입 쿠폰 / PC → 회원 목록에 '시연 고객' / 왼쪽 숫자 '추천 보상: 대기'
**말:** "친구를 추천한 하늘님의 보상은 아직 '대기'입니다. 새 손님이 실제로 와야 지급됩니다."

## 4단계 · 매장 체크인 (30초)
**누를 것:** **고객 · 오늘의 코드로 체크인**
**보일 것:** 휴대폰 → 이용 내역 '확인 대기' / PC → '지금 처리할 일' 숫자 +1
**말:** "손님이 코드만 입력해서는 아직 실적이 아닙니다. 직원 확인이 필요합니다."

## 5단계 · 직원이 한 번 눌러 확인 — 핵심 장면 (60초)
**누를 것:** **직원 · 직원으로 방문 확인** (또는 오른쪽 PC 화면 맨 위의 '방문 확인'을 직접 클릭)
**보일 것:** 왼쪽 초록 상자 **방금 바뀐 것** — 스탬프 0→1, 추천 보상 대기→확정, 확인 대기 −1, 오늘 확인 방문 +1 / 휴대폰 스탬프 1/10
**말:** "직원이 버튼 하나를 누르면 손님 혜택, 추천한 친구 보상, 성과 기록이 동시에 바뀝니다. 같은 버튼을 다시 눌러도 두 번 지급되지 않습니다."

## 6단계 · 운영 AX 에 남은 결과 (40초)
**보일 것:** PC → 이 손님의 회원 상세(확인 이용 1회·쿠폰·추천) / 왼쪽 '이 손님 관련 성과 기록'
**말:** "직원이 확인한 것만 실적으로 셉니다. 클릭이나 자가신고는 참고 신호로만 씁니다."

## 7단계 · 관심 → 안내 → 다시 방문 — 시나리오 B (90초)
**누를 것 (순서대로 3개):**
1. **고객 · 닭가슴살 샐러드 저장** → PC 회원 상세 '최근 관심'에 표시, '관심 메뉴 안내를 검토해 보세요' 제안
2. **책임자 · 관심 안내 승인·발송** → 알림 수신에 동의한 '최근 관심 회원'에게만 앱 알림 (7일 안에 같은 알림 받은 사람은 자동 제외)
3. **고객 · 알림 눌러 메뉴 보기** → 휴대폰이 저장한 메뉴로 이동
**보일 것:** 왼쪽 '알림 결과' — 발송 · 확인 1 · 후속 행동 1 · **확인 방문 0**
**말:** "알림을 열고 메뉴를 본 것은 관심 신호일 뿐입니다. 손님이 실제로 다시 와서 직원이 확인해야 '확인 방문'이 늘어납니다. 그래서 숫자를 부풀리지 않습니다."

## 8단계 · 지금 · 다음 · 이후 (60초)
**보일 것:** 왼쪽 3칸 — 지금(DEMO) / 다음(실제 매장 운영) / 이후(유료 웰니스 사업)
**말:** "지금은 구조를 확인하는 시연입니다. 실제 매장에서 쓰려면 서버·로그인·권한을 붙이는 단계가 필요하고, 거기서 쌓인 확인 이용과 관심 기록이 AI 식단·구독·반려묘 관리·커머스의 근거가 됩니다."
**꼭 말할 것:** 지금 없는 것 — 외부 AI API · 실제 결제 · POS · 카카오/푸시 발송 · 서버 기반 다중 사용자.

## 막혔을 때
| 상황 | 할 일 |
|---|---|
| 실행 버튼이 회색 + "먼저 '…'을 실행해야 해요" | 옆의 **N단계로 이동** 을 눌러 앞 단계를 실행 |
| 버튼이 '— 완료' 로 회색 | 이미 실행됨. 다음으로 진행 (다시 눌러도 중복 반영 안 됨) |
| 새로고침했다 | 같은 단계·같은 데이터로 돌아옴. 주소에 단계가 없으면 **이어서 하기** |
| 화면이 이상하게 꼬였다 | **처음부터** → 1단계부터 (30초 안에 3단계까지 다시 갈 수 있음) |
| 오른쪽 화면이 작다 | **운영 AX 크게 / 손님 앱 크게** |
| 인터넷이 끊겼다 | 앱은 인터넷이 필요합니다 — 노트북 핫스팟 준비 |

## 정직하게 말할 것
- 모든 숫자는 **DEMO 시연 데이터** (이 브라우저 안). 실제 매출·회원이 아닙니다.
- 휴대폰과 PC 화면은 **같은 브라우저** 안에서 이어진 것입니다. 서로 다른 기기 사이 실시간 동기화는 서버를 붙이는 다음 단계에서 됩니다.
- 고양이 14마리는 매장 카드 기준 실제 정보, 메뉴 사진 일부는 샘플입니다.
- 추천·안내 대상은 **규칙**으로 고릅니다 (AI 모델 아님).
